## 3.1 后端技术选型

### 选型结论

| 项 | 选型 | 版本要求 | 阶段 |
|----|------|---------|------|
| 语言 | Python | ≥ 3.11 | P0 |
| Web 框架 | FastAPI | ≥ 0.115 | P0 |
| ASGI 服务器 | uvicorn | ≥ 0.30 | P0 |
| 向量数据库 | ChromaDB | ≥ 0.5 | P0 |
| 文档元数据 | SQLite | 标准库 | P0 |
| Embedding 模型 | sentence-transformers | ≥ 3.0 | P0 |
| LLM | OpenAI 兼容 API | — | P0 |
| PDF 解析 | PyMuPDF（主） | — | P0 |
| 前端 | 手写静态 HTML/CSS/JS；挂载 `/sz`、`/sz-cfg`、`/shared` | — | P0 |
| Agent 编排 | LangGraph | ≥ 0.2 | P2 可选 |

### 为什么选 Python + FastAPI

选择 Python：项目核心依赖 ChromaDB、sentence-transformers、PyMuPDF 等均为 Python 生态一等公民。选其他语言意味着跨语言调用 Python 脚本，凭空增加复杂度。

选择 FastAPI：自动生成 OpenAPI 文档、Pydantic 参数校验、原生异步支持、社区活跃。

不选其他方案的理由：

| 方案 | 不选的原因 |
|------|-----------|
| Flask | 无自动参数校验、无自动 API 文档、无原生异步 |
| Django | 自带 ORM、模板引擎，本项目不需要，太重 |
| Node.js + Express | ML 生态全在 Python 侧，跨语言调用得不偿失 |
| Go + Gin | Go 的 ML 库生态远不如 Python |
| 纯 Streamlit | 业务逻辑易嵌入 UI；本项目 API 与 UI 分离 |

当前项目需要 FastAPI，但保持克制。P0 仅 3 个 API；Next.js 前端不写 RAG 逻辑，通过 CORS 调后端。克制使用——只用路由、参数校验、异常处理、CORSMiddleware，不生造概念。

MVP 不引入 LangGraph：RAG 入库/检索/问答由自研 `services/` 编排（`query.py` 串联 retrieval + generation）。P2 若做多步 Agent（如循环查库、自动出题流水线），再引入 **LangGraph** 包在现有 `/ask`、retrieve 能力之外，不替换 RAG 主链路。

## 3.2 语言工程规范

### 依赖管理

工具用 uv（已安装在 WSL 上），锁定文件为 uv.lock，依赖声明在 pyproject.toml。

规则：
- 新增依赖用 `uv add <package>`，不手写 pyproject.toml
- 间接依赖由 uv 锁定，不手动改 uv.lock
- venv 放在 WSL 本地路径（如 `~/exam-rag/.venv`），不在 `/mnt/` 上创建。Windows 挂载点 IO 极慢，venv 创建会超时
- 不走 pip install，全部走 uv

### 配置读取

优先级：环境变量 > .env 文件 > 代码默认值。

规则：
- API Key、数据库路径等敏感参数走环境变量，不硬编码
- 应用级参数（chunk_size、temperature、retrieval_threshold）集中放 `src/config.py` 的 dataclass
- .env 不提交到 git，提供 .env.example 模板
- config.py 中用 dataclass 定义配置组（如 LLMConfig、StorageConfig），api_key 和 base_url 从环境变量读取

### 日志

使用 Python 标准库 logging，不引入第三方框架。日志级别：DEBUG（开发调试）、INFO（关键节点）、WARNING（可恢复异常）、ERROR（需关注错误）。禁止 print()。每个模块顶部通过 `logging.getLogger(__name__)` 获取 logger，日志调用用 logger.info/warning/error。

### 异常处理

业务异常统一在 `src/exceptions.py` 中定义 AppException 基类（携带 status_code 和 message），具体异常类型（NotFoundException / BadRequestException / LLMTimeoutException）继承它。外部库异常在调用处捕获后转为业务异常。不写 except Exception: pass。

全局异常处理器在 src/main.py 注册，统一捕获三类：
1. 业务异常 → 转为标准错误响应
2. 参数校验异常 → FastAPI 自动处理返回 422
3. 未预期异常 → 记录 traceback，返回 500

services 层不捕获异常（除非转为特定业务异常）。apis 层不写 try/except。

### 测试

测试框架 pytest。**覆盖核心链路**（对话 / 入库 / 检索隔离），不镜像每个工具函数：

| 文件 | 覆盖 |
|------|------|
| `test_api` | HTTP：目录、上传/扫描/删除、ask 校验、配置与 LLM 注册 |
| `test_ask` | 对话：流式、qa\|concept\|chapter、prompt、章节匹配、拒答 |
| `test_retrieval` | 检索：`course_id` 隔离、阈值、BM25/RRF、精排路径 |
| `test_ingest` | 入库：分块、force 扫描、chapter、acquire/fail、存储隔离 |
| `test_parsing` | 解析：MD/TXT/DOCX/PPTX |
| `test_golden_qa` | golden 冒烟（`@integration`） |
| `test_integration` | 端到端入库+问答（`@integration`） |

离线 Recall@K / MRR 用 `tests/eval/run_retrieval_eval.py`，不进默认 pytest。

## 3.3 框架最佳实践

FastAPI 编程遵循官方文档：用 APIRouter 按业务域拆分路由，在 `apis/router.py` 聚合后在 `main.py` 一次性挂载（参考 full-stack-fastapi-template 的 `api/main.py` 模式）。需要复用的组件通过 Depends 注入，在 src/dependencies.py 中用 @lru_cache() 包装工厂函数确保单例。参数校验用 Pydantic BaseModel + Field 声明。仅使用 CORSMiddleware 允许前端跨域。

## 3.4 框架最大化利用

| 需求 | 使用 FastAPI 自带 | 不手写替代方案 |
|------|------------------|----------------|
| HTTP 状态码 | starlette.status | 不手写数字 |
| 参数校验 | Pydantic Field | 不手写 if |
| 错误返回 | HTTPException | 不 return 自定义 json |
| 全局异常处理 | @app.exception_handler | 不每个接口 try/except |
| API 文档 | 框架自动生成 /docs | 不手写文档 |
| 路由分组 | APIRouter(prefix, tags) | 不堆一个文件 |

## 3.5 接口响应规则

成功-列表：`{"code": 200, "data": {"items": [...], "total": 总条数, "page": 当前页, "page_size": 每页条数}}`

成功-对象：`{"code": 200, "data": {"id": "资源标识", "content": "内容", "source": "来源"}}`

失败：`{"code": HTTP状态码, "message": "错误描述", "detail": "详细信息（可选）"}`

错误码映射：

| 场景 | HTTP | message 示例 |
|------|------|-------------|
| 参数校验失败 | 422 | 问题内容不能为空 |
| 资源不存在 | 404 | 该资料不存在 |
| LLM 超时 | 504 | AI 服务响应超时 |
| LLM API 错误 | 502 | AI 服务暂时不可用 |
| 资料格式不支持 | 400 | 仅接受 PDF/TXT/MD |
| 未预期错误 | 500 | 服务器内部错误 |

不自定义业务错误码，HTTP 状态码足够。detail 仅 DEBUG 模式返回。

## 3.6 日志规则

| 场景 | 级别 | 示例 |
|------|------|------|
| 入库流程节点 | INFO | 入库完成，处理了 320 个 chunk |
| 检索耗时 | INFO | 检索完成，耗时 1.2s |
| 文件解析失败 | WARNING | PDF 解析失败: xxx，跳过 |
| LLM API 超时 | ERROR | DeepSeek API 调用超时 (60s) |

不自定义日志格式，用 uvicorn 默认。开发阶段输出到 stderr 即可。

## 3.7 数据库连接方式

MVP 使用 **ChromaDB（向量）+ SQLite（元数据）**，不使用 PostgreSQL。原因：单课本地部署，无用户系统；两者均可文件持久化，零服务依赖。

连接方式：
- 在 `services/storage/` 定义 `VectorStore`、`DocStore` 协议及实现
- 通过 `dependencies.py` 中 @lru_cache 工厂注入，按 config 选择实现
- 业务代码不得直接 `chromadb.PersistentClient` 或裸 `sqlite3.connect`

启动时须验证 ChromaDB 与 SQLite 连通性（startup 事件），失败则阻止启动。后续换 PostgreSQL + pgvector 时，仅替换 `storage/` 实现，见 [02-模块架构.md](./02-模块架构.md) §2.8。

## 3.8 健康检查

提供 GET /api/v1/health 端点，无鉴权。检查项：ChromaDB + SQLite + LLM API，各检查独立执行。

全部正常返回：

```json
{"code": 200, "data": {"status": "healthy", "chromadb": "ok", "sqlite": "ok", "llm": "ok"}}
```

部分异常返回 `{"code": 503, "data": {"status": "degraded", ...}}` 并标出哪项不可用。

/api/v1/health 不记日志。前端可用此端点做启动等待。

## 3.9 权限校验入口

当前不做权限校验。系统面向单个课程小组，部署在内网或本地，无多用户体系。如果后续需要，预留方案一 Dependency（粒度可控）和方案二中间件（全局拦截需维护白名单）。

`dependencies.py` 提供 `get_current_user() -> None`，MVP 固定返回 None。

## 3.10 项目启动方式

后端 + 前端同端口：`uv run exam`（端口读 `.env` 中 `PORT`，默认 8787）。

```bash
uv sync
uv run exam
# → http://127.0.0.1:<PORT>/sz/       工作台
# → http://127.0.0.1:<PORT>/sz-cfg/   设置
# → http://127.0.0.1:<PORT>/docs      OpenAPI
# → http://127.0.0.1:<PORT>/api/v1/health
```

有 `www/sz/` 时 `GET /` 重定向到 `/sz/`；否则到 `/docs`。无前端构建步骤，改 `www/` 下静态文件后刷新即可。
