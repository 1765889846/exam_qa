# 02 模块架构

> RAG 复习助手 · 目录、流水线、数据模型、API  
> 2026年6月 · 方案设计阶段

---

## 2.1 分层与职责

```
本地端 Agent   用户本机：入库 / 检索 / 生成 / 拒答（services/ 编排）
    ↑ HTTP
网页端 Agent   浏览器 UI：发问 / 上传 / 配置（web/ 源码 → www/ 静态挂载）
    ↓
apis/          HTTP 出口：路由、参数校验、Depends 注入
    ↓
services/      业务逻辑（不 import FastAPI）
    ↓
storage/       向量库 + 文档元数据（services 通过抽象接口调用）
```

**依赖规则**：
- `apis/` 只做 HTTP，不写 RAG 细节
- `services/` 不 import FastAPI
- `apis/` 不写 try/except（由全局异常处理器统一处理）
- `services/` 不捕获异常（除非转为 AppException）

## 2.2 services 划分

| 模块 | 文件 | 职责 |
|------|------|------|
| 入库 | `services/ingestion.py` | 解析 → 分块 → 向量化 → 写入 storage |
| 查询编排 | `services/query.py` | 按 mode 路由，串联检索与生成 |
| 检索 | `services/retrieval.py` | 向量检索；P1 混合检索；P2 精排入口 |
| 生成 | `services/generation.py` | 拼 prompt、调 LLM、组装 citations |
| 存储 | `services/storage/` | `vector_store.py`、`doc_store.py` |
| LLM | `services/llm.py` | OpenAI 兼容 API 调用、Embedding |

**对外入口**（services 层）：

```python
ingestion.ingest_file(path) -> doc_id
query.ask(question, mode="qa") -> Answer
```

## 2.3 入库流程

```
POST /api/v1/documents
  → apis/v1/documents.py
  → services/ingestion.py
       → 解析（pdf / txt / md；P1: ppt）
       → 分块
       → 向量化（sentence-transformers）
       → storage.vector_store.upsert + storage.doc_store.update_status
```

## 2.4 查询流程

```
POST /api/v1/ask
  → apis/v1/ask.py
  → services/query.py
       → 按 mode 选策略（P0 仅 qa）
       → services/retrieval.py 检索
       → 后处理：置信度截断、拒答（P2：精排）
       → services/generation.py 生成
       → 返回 answer + citations + grounded
```

P1 起请求体增加 `mode` 字段（`qa` | `concept` | `chapter`），不新增 HTTP 端点。

## 2.5 目录结构

```
exam-rag/
├── data/                          # 原始资料（gitignore）
│   └── knowledge/                 # 入库文件：{doc_id}/{filename}
├── storage/
│   ├── chroma/                    # ChromaDB 向量持久化目录
│   └── meta.db                    # SQLite：文档元数据、入库状态
├── src/
│   ├── main.py                    # FastAPI 应用入口；注册路由与全局异常处理
│   ├── config.py                  # 全局配置（LLM、存储路径、chunk_size 等 dataclass）
│   ├── dependencies.py            # Depends 工厂：注入 VectorStore、DocStore、LLM；鉴权占位
│   ├── exceptions.py              # 业务异常 AppException 及子类
│   ├── models.py                  # Pydantic 请求/响应模型（AskRequest、Citation 等）
│   ├── apis/                      # HTTP 层，不含 RAG 逻辑
│   │   ├── router.py              # 聚合 api_router，main.py 只 include 一次
│   │   └── v1/                    # 版本化端点（prefix=/api/v1 在 main.py 挂载）
│   │       ├── health.py          # GET /api/v1/health
│   │       ├── config.py          # GET /api/v1/config（工作台配置页）
│   │       ├── documents.py       # POST /api/v1/documents
│   │       └── ask.py             # POST /api/v1/ask
│   ├── web_static.py              # 挂载 www/ 静态工作台
│   ├── services/                  # 业务逻辑（不 import FastAPI）
│   │   ├── ingestion.py           # 入库编排：解析 → 分块 → 向量化 → 写入 storage
│   │   ├── query.py               # 查询编排：按 mode 调 retrieval + generation，组装 Answer
│   │   ├── retrieval.py           # 检索：向量相似度搜索；P1 混合检索；P2 精排入口
│   │   ├── generation.py          # 生成：拼 prompt、调 LLM、格式化 citations 与 grounded
│   │   ├── llm.py                 # LLM / Embedding 客户端（OpenAI 兼容 API）
│   │   └── storage/
│   │       ├── vector_store.py    # 向量存取：upsert、search、delete_by_doc_id（Chroma 实现）
│   │       └── doc_store.py       # 文档元数据 CRUD：create、update_status、get、list（SQLite）
│   └── utils/                     # 与业务无关的通用工具函数
├── web/                           # Next.js 源码（pnpm workspace）
│   ├── app/                       # App Router：/ask、/documents、/settings
│   ├── components/
│   └── lib/api/                   # fetch 封装，NEXT_PUBLIC_API_BASE
├── www/                           # 静态工作台（pnpm build 生成，FastAPI 挂载）
├── tests/
│   ├── test_health.py
│   ├── test_ingest.py
│   ├── test_ask.py
│   └── fixtures/
│       ├── sample.txt
│       └── golden_qa.jsonl
├── pyproject.toml                 # 后端 Python 依赖（uv）
├── .env.example
└── .gitignore
```

**目录约束**：
- 新增业务域时，在 `apis/v1/` 和 `services/` 各加文件，在 `models.py` 加模型
- `main.py` 通过 `app.include_router(api_router, prefix=API_V1_PREFIX)` 挂载，不在 main 里逐个 include
- 不往 `src/` 根目录堆文件
- 向量与元数据通过 `services/storage/` 访问，业务代码不直接调用 Chroma / sqlite3

## 2.6 数据模型

**Chunk 元数据**（写入 Chroma，字段预留扩展）：

```python
{
    "doc_id": str,
    "source_file": str,
    "page": int | None,
    "chunk_index": int,
    "course": "信号与系统",
    "chapter": str | None,
    "doc_type": str | None,   # 教材 | 重点 | 真题 | 公式
}
```

**SQLite `documents` 表**：

```sql
id, filename, file_path, status, chunk_count, course, created_at
-- status: pending | processing | done | failed
```

删文档须同时更新 `doc_store` 并 `vector_store.delete_by_doc_id()`，避免孤儿数据。

## 2.7 API 端点

| 方法 | 路径 | 阶段 | 说明 |
|------|------|------|------|
| GET | `/api/v1/health` | P0 | Chroma + SQLite + LLM |
| POST | `/api/v1/documents` | P0 | 上传并入库 |
| POST | `/api/v1/ask` | P0 | 问答；P1 起支持 `mode` |

> 版本前缀由环境变量 `API_V1_PREFIX` 控制，默认 `/api/v1`。

**POST /ask 响应示例**：

```json
{
  "code": 200,
  "data": {
    "answer": "...",
    "citations": [
      {"source_file": "第3章.pdf", "page": 12, "snippet": "...", "score": 0.85}
    ],
    "grounded": true
  }
}
```

响应格式遵循 [03-工程规范.md](./03-工程规范.md) §3.5。

## 2.8 扩展预留

| 扩展项 | 做法 |
|--------|------|
| 混合检索 / 精排 | 扩展 `services/retrieval.py`，`query.py` 不改签名 |
| 新查询模式 | 在 `services/query.py` 加 mode 分支 + `generation.py` 加 prompt |
| 换 PostgreSQL + pgvector | 替换 `storage/` 实现，services 层接口不变 |
| 用户鉴权 | `dependencies.get_current_user()` 占位，MVP 返回 None |
| 多学科隔离 | P1-A：`course_id` + 检索 filter；见 [04-后续演进规范.md](./04-后续演进规范.md) §4.2 |
| Agent 编排 | P2-B：LangGraph 包在 RAG 外；见 [04-后续演进规范.md](./04-后续演进规范.md) §4.4 |

## 2.9 实施顺序

```
Step 1  脚手架：main + config + apis/v1/health.py
Step 2  services/storage/：VectorStore + DocStore
Step 3  services/ingestion.py + apis/v1/documents.py
Step 4  services/retrieval.py + generation.py + query.py + apis/v1/ask.py
Step 5  web/ + www/：Next.js 工作台（/ask、/documents、/settings）
Step 6  pytest + golden_qa.jsonl
```

每步验收通过后再进入下一步。启动与环境变量见 [03-工程规范.md](./03-工程规范.md) §3.10。
